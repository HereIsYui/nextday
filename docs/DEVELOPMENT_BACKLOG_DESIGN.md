# 《择日飞升：九塔封魔》研发 Backlog 拆分 v1.2

## 一、定位

本文把当前 GDD 和专项文档转化为研发任务拆分，用于后续排期、接口设计和测试计划。首轮开发以 `30-45 天小纪元 MVP` 为目标，先验证 Web + API 主循环，再接入 H5/PWA 和鱼排聊天室插件。

技术默认采用全栈 TypeScript：Next.js + React 实现独立 Web 与 H5/PWA，NestJS 实现后端 API，PostgreSQL + Redis 支撑存储、缓存和异步队列。鱼排聊天室右侧插件采用“小卡片默认态 + 复杂窗口展开态”：默认只显示当前状态和少量快捷功能，点击后打开日课、洞府、九州 / 九塔、战报、古宝、月卡和宗门提醒窗口。

2026-07-06 起，后续产品方向重定为“九州城池 SLG”。旧 P0-P3 已完成内容保留为素材库和可迁移系统，但不再继续以“今日修行 + 九塔封魔日课”为主轴追加功能。新路线详见 [《九州城池纪元》重策划案](JIUZHOU_CITY_ERA_DESIGN.md)，后续研发按 `R0-R6` 重构阶段推进。

脚本点击处理原则：

- 不禁止普通脚本点击。
- 不做强验证码、不做前端反自动化对抗、不做浏览器指纹封锁。
- 行为风控只做记录、评分、限频、收益延迟结算、异常标记和后台审核。
- 脚本可以减少点击，但不能突破行动令、权益档位、奖励公式、托管权限和贡献衰减。

## 五、行为风控边界

- 不禁止普通脚本点击。
- 不因为脚本点击直接封禁账号。
- 不没收付费仙玉，付费资产处理必须人工审核。
- 风控优先处理高影响玩法：PVP、九塔贡献、交易行、宗门仓库、抽卡订单。
- 普通领取、普通探索、洞府收菜只做限频和日志，不做重处罚。
- 脚本点击不得突破：行动令、批量上限、托管权限、策略槽位、奖励公式、贡献衰减。
- M6 已落地 `behavior_risk_record`、`delayed_settlement_record`、后台风险查询、延迟结算审核、瞬时接口限频、PVP 衰减记录、九塔延迟结算和便利权益越权记录。
- M7 已落地 Web 分区主界面、H5 / PWA 底部导航、插件小状态卡片、展开面板、插件一键领取和预设行动提交接口。
- M8 已落地 GM 查询聚合、补偿邮件、公告、配置发布 / 回滚、GM 操作日志、风控记录解除和 Admin 工作台。
- M9 已落地 `test:m9` 总体验收：覆盖 P0 配置回归、新手闭环、生产成长、九塔 / Boss / 宗门 / PVP 异步玩法、月卡 / 古宝 / 便利权益、脚本行为风控、GM 邮件公告、排行、称号展示和小纪元复盘数据。

## 六、重要接口与返回约定

- 新增风险查询后台接口：查看玩家风险分、命中规则、关联日志。
- 状态变更接口继续使用 `Idempotency-Key`。
- 行动提交、PVP、九塔、交易、宗门仓库需要返回风控状态：正常、延迟结算、收益衰减、人工审核。
- 月卡托管仍必须是服务端权益能力；免费脚本不能通过抓包创建托管队列。

## 十、验收场景

- P0 开发任务能支撑 30-45 天小纪元 MVP 测试。
- M3 生产成长可通过 Web 和 API 完成炼丹、服丹、炼器、淬炼、铭刻、分解和技能预设保存。
- 炼器结果不得产出九大古宝，九大古宝仍只属于专属池和后续 M5 商业化模块。
- 服丹递减、词条锁定、法宝锁定分解、生产记录和幂等键均可自动化回归。
- M4 多人玩法可通过 Web 和 API 完成九塔行动、Boss 镜像挑战、宗门创建 / 任务 / 仓库、资源点 PVP 和四类排行查询。
- 九塔、Boss、宗门和 PVP 均支持异步提交，不要求固定时间在线。
- PVP 失败不掉级、不爆付费道具、不摧毁核心法宝；重复目标会触发收益衰减。
- 宗门仓库只允许未绑定白名单材料入库，付费、绑定、限定产物不可流通。
- 排行奖励预览只包含灵石、普通材料和展示向奖励，不发唯一战力道具。
- M5 商业化可通过 Web 和 API 完成小月卡 / 大月卡购买、月卡日权益领取、常驻机缘池抽取、九大古宝池赠抽 / 残页抽取、VIP 同步、便利预览、托管队列和展示外观装备。
- 九大古宝池结果只来自 9 件古宝；当前只允许月卡赠抽和九大古宝残页合成，仙玉直抽入口返回未开放，不扣仙玉、不写成功记录、不计保底。
- 常驻机缘池支持绑定仙玉或付费仙玉抽取，抽卡记录和保底状态可回放。
- VIP3 便利等同小月卡，VIP4 高于小月卡但不高于大月卡；VIP 不提供九大古宝赠抽。
- 免费、VIP、小月卡、大月卡的奖励公式一致，只体现便利差异。
- 免费账号伪造批量 20 次，服务端拒绝或截断为免费上限。
- 免费账号调用大月卡托管队列，返回无权限。
- 展示外观只影响展示状态，接口返回 `stat_bonus: null`，不改变角色等级、战力、奖励倍率或贡献倍率。
- 高频固定间隔请求触发风险分增加，但普通收益不被无故吞掉。
- 同一 PVP 目标连续攻击触发收益衰减。
- 同设备多账号刷九塔补给触发贡献延迟结算。
- 风控命中的收益可在后台审核、发放或回滚。
- 所有风控处理均保留日志，可追溯到玩家、接口、记录 ID 和规则版本。
- M8 运营后台可通过 `X-Admin-Token` 查询玩家运营档案，覆盖订单、抽卡、战斗、行动、货币、邮件、日志和风控摘要。
- 补偿邮件会拦截付费仙玉、限定法宝和九大古宝等禁止奖励。
- 配置发布会校验九大古宝池只包含 9 件古宝，且当前不开放付费仙玉直抽；配置可发布和回滚。
- 风控记录可人工解除，延迟结算可放行或驳回，所有后台处理写入 GM 操作日志。

## 十一、默认假设

- MVP 不做强反外挂，不做浏览器指纹封锁，不做验证码常态化拦截。
- 行为风控只服务公平、稳定和运营审计，不把正常自动点击当成违规。
- 月卡价值来自服务端托管、队列长度、策略槽和便利能力，不来自更高奖励倍率。
