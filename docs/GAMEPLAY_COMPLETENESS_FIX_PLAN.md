# 《择日飞升》现有玩法闭环修复计划 v1.0

## 一、文档目标

本文只修复已经存在的玩法、接口和数据模型，不新增玩法类型。

本轮目标：

- 探索只保留长期探索，彻底删除按次数定时探索。
- 长期探索不再等玩家结束行动后一次性结算，而是持续产生收益。
- 长期探索和长期修炼继续互斥，并统一遵守最多 8 小时的离线收益规则。
- 修复装备、技能、战力和长期行动之间的规则断裂。
- 补齐已有后端能力在 Web 和文字端缺少的操作闭环。
- 删除“今日路线”和其他已经退役流程的残留。

完成后的判断标准不是“接口存在”，而是玩家可以从入口进入、完成操作、看到结果，并且结果真实参与后续玩法。

## 〇、当前实施状态（2026-08-09）

第一阶段的长期探索主链已落地，后续更新应以本节和下面的规则为准：

- 已完成：长期探索启动、修炼/探索互斥、不消耗行动令、分钟级时间游标、小时级在线批量结算。
- 已完成：探索按每日 21 场基准累计生成战斗，在线收益直接入账，结束探索只补齐完整分钟。
- 已完成：离线最多 8 小时、离线快照可重复查看、领取接口幂等，Web 以居中弹窗确认领取。
- 已完成：探索奇遇继续独立触发，手动选择和超时自动选择沿用原有幂等结算。
- 已完成：Web 轮询在探索战斗新增后合并发送“九州传音”，不再显示“领取探索”旧按钮。
- 已完成：删除旧 `explore/current`、`explore/claim` 路由、客户端方法和“领取探索”文字入口；旧请求不再进入结算。
- 已完成：清理仅用于历史只读数据的共享探索响应类型，并为长期行动回归测试增加结算账本断言。
- 已完成：新增 `ActionSettlementRecord`，按行动与起止游标建立唯一窗口，记录在线/离线来源、有效分钟、战斗引用、奖励快照和规则版本。
- 已完成：开发环境商业化模拟必须显式开启开关并携带开发令牌，生产环境继续只接受 FishPi 验证订单。
- 进行中：迁移仍直接调用旧 HTTP 路由的历史测试，并补齐跨模块统一资源锁、并发审计及外围玩法 Web 操作闭环。

后续每次修改需要同时更新“实施状态”、对应验收用例和发布检查，不得只改 Web 文案而遗漏服务端时间游标或离线快照。

## 二、范围与非目标

- 长期修炼与长期探索。
- 探索战斗、奇遇、战报和奖励。
- 装备、技能和统一战力。

- 不新增地图、玩法、副本、资源类型或付费项目。
- 不恢复今日路线、下一步推荐或强制新手指引。
- 不引入实时 PVP、交易行或新的社交关系。
- 不改变九境三阶段的成长预算。
- 不提高月卡、VIP 或外观的战力和掉落倍率。
- 本期继续使用 HTTP 轮询，不引入 WebSocket、Web Push 或常驻玩家级定时器。

## 三、长期探索最终规则

### 3.1 唯一入口

探索只保留长期行动模式：

```text
探索
探索 <州域>
结束探索
```

规则：

- `探索` 在 Web 打开州域选择，在文字端返回可选州域。
- `探索 <州域>` 开始长期探索。
- 不再接受探索次数，`探索 冀州 1` 等旧格式返回明确的语法错误。
- 删除“领取探索”；探索在线收益自动入账，离线收益通过统一离线收益弹窗领取。
- 长期修炼与长期探索同一时间只能存在一项。
- 结束探索只关闭行动并补齐尚未落账的完整分钟，不再生成一笔覆盖整个行动时长的大额结算。

### 3.2 结算粒度

采用“分钟级计账、小时级批量落账”：

- 计账精度：1 分钟，只计算完整分钟。
- 在线自动结算周期：60 分钟。
- 页面重新获得焦点、状态轮询、切换州域、结束行动时，服务端先尝试补结算。
- 不为每个玩家创建系统计时器；服务端根据结算游标按需补算，重启后也可恢复。
- 后续如果需要提高反馈频率，只调整结算周期配置，不改变分钟级账本和奖励公式。

默认配置：

```text
LONG_ACTION_ACCOUNTING_MINUTES = 1
LONG_ACTION_SETTLEMENT_MINUTES = 60
LONG_ACTION_OFFLINE_CAP_MINUTES = 480
LONG_ACTION_ONLINE_HEARTBEAT_SECONDS = 60
STANDARD_DAILY_EXPLORE_BATTLES = 21
```

在线与离线的判定：

- Web 在长期行动进行中每 60 秒刷新行动状态，同时更新服务端 `lastActiveAt`。
- 页面隐藏、关闭或心跳中断后，从最后一次有效心跳开始进入离线时间窗口。
- 服务端处理回归请求时必须先生成离线收益快照，再更新 `lastActiveAt`，不能先覆盖离线起点。
- 在线心跳只触发按需结算，不要求为玩家创建常驻后台任务。
- 插件和 API 调用也可以刷新状态，但只有明确的行动状态请求更新在线心跳，普通聊天轮询不算在线探索。

本次周期结算只改变长期探索：

- 长期探索在线收益按小时自动入账。
- 长期修炼仍保留“结束行动后领取行动收益”的现有操作方式。
- 两种行动共享互斥锁、时间游标和离线 8 小时上限，不能获得重叠时段收益。

### 3.3 探索场次生成

长期探索不按“每小时固定一战”直接取整，避免日收益从 21 次被放大为 24 次。

```text
累计应结算场次 = floor(有效探索分钟 × 21 ÷ 1440)
本次新增场次 = 累计应结算场次 - 已结算场次
```

要求：

- 不足一个完整场次的进度保留在行动记录中。
- 每个新增场次独立生成确定性随机种子、敌人、胜负、掉落和战报。
- 同一行动、同一场次重复补算必须返回相同结果，不能重复发奖。
- 开始后立即结束通常得到 0 场收益，不再强制保底 1 场。
- 奇遇按已经完成的探索场次触发，不能通过反复开始、结束刷触发次数。

### 3.4 在线收益

- 在线达到一个结算周期后，修为、灵石、材料和任务进度直接入账。
- 同一周期产生的多场战斗合并为一条“九州传音”，战报仍逐场保存。
- 当前行旅展示州域、开始时间、本周期进度、累计场次和最近一次收益。
- 玩家不需要点击领取在线收益。
- 在线周期不足 60 分钟时，结束行动会按完整分钟计算可新增场次并立即入账。

### 3.5 离线收益

离线规则与现有修炼规则统一：

- 单次离线最多计算 8 小时，即 480 个完整分钟。
- 超过 8 小时的部分不产生探索收益，也不能通过重复刷新补领。
- 玩家领取时无论离线是否超过 8 小时，计账游标都推进到本次回归时间；被上限截断的时间永久丢弃。
- 重新打开 Web 后先展示离线收益弹窗，列出离线时长、探索场次、胜负、修为、灵石和物品。
- 玩家点击“领取”后才在一个事务中入账，并推进离线结算游标。
- 生成离线快照后暂停新的在线探索结算；领取完成后以领取时间建立新的在线结算窗口。
- 离线期间产生的奇遇可以进入待选择状态；长时间未选择时沿用“优先修为选项，否则第一个选项”的自动选择规则。
- 页面关闭期间不补发实时弹窗；下次打开只展示尚未领取的离线汇总。
- 修炼和探索共享同一个离线时间窗口，不能在同一时间段同时获得两类离线收益。

### 3.6 行动切换

- 进行中的行动必须先结束，才能开始另一项行动。
- 结束时先锁定玩家、补结算最后一段完整分钟，再关闭行动。
- 已经存在待领取离线收益时，可以结束行动，但必须先领取该收益才能开始下一项行动。
- 切换行动后新行动使用新的时间游标，不能继承旧行动未满一分钟的余量。

## 四、长期行动数据与事务设计

### 4.1 数据模型

将长期修炼和长期探索统一为可审计的行动记录。本轮在现有行动游标之外新增 `ActionSettlementRecord` 探索结算账本；实现必须满足以下数据语义：

| 字段 | 说明 |
| --- | --- |
| `actionId` | 长期行动唯一标识 |
| `playerId` | 玩家标识 |
| `actionType` | `cultivation` 或 `explore` |
| `provinceId` | 探索州域，修炼为空 |
| `startedAt` | 行动开始时间 |
| `endedAt` | 行动结束时间 |
| `accountedUntil` | 已完成分钟计账的时间游标 |
| `settledUntil` | 已经实际入账的时间游标 |
| `settledMinutes` | 已结算有效分钟数 |
| `settledBattleCount` | 探索已生成战斗数 |
| `lastActiveAt` | 最后一次有效行动心跳，用于区分在线与离线 |
| `pendingOfflineSnapshot` | 尚未领取的离线收益快照 |
| `status` | `active`、`offline_claimable`、`ended` |
| `configVersion` | 行动规则版本 |

新增结算记录，唯一键至少包含：

```text
actionId + settlementStartAt + settlementEndAt
```

结算记录保存：

- 在线或离线来源。
- 有效分钟数。
- 新增探索场次数。
- 奖励快照。
- 战报引用。
- 幂等键和规则版本。

### 4.2 统一事务

每次补结算必须进入统一玩家事务：

```text
事务开始
  -> pg_advisory_xact_lock(playerId)
  -> 读取最新行动和结算游标
  -> 计算有效时间窗口与离线上限
  -> 预占唯一结算窗口
  -> 逐场生成战斗和奖励
  -> 通过统一资源与修为结算服务入账
  -> 更新任务、州域进度和行动游标
  -> 写入结算、奖励、钱包和战报日志
事务提交
```

约束：

- 不允许先发奖励再更新游标。
- 任何异常必须整体回滚。
- 两个不同幂等键并发补算同一窗口时，只能有一个成功发奖。
- 服务重启、请求超时或客户端重试后不能丢失或重复结算。

## 五、旧探索流程删除清单

### 5.1 API 与服务

- `POST /api/game/explore` 改为仅启动长期探索，移除 `count` 语义。
- 删除 `GET /api/game/explore/current`，统一使用 `GET /api/game/actions/current`。
- 删除 `POST /api/game/explore/claim`，统一使用在线自动结算和离线收益领取。
- 增加 `GET /api/game/actions/offline-reward`，返回固定的待领取离线收益快照。
- 增加 `POST /api/game/actions/offline-reward/claim`，领取修炼或探索的离线收益。
- 保留 `POST /api/game/actions/claim`，但只用于领取已经结束的长期修炼收益。
- 删除旧探索倒计时、行动令扣除、`pending/completed/claimed` 队列状态和按次数循环结算。
- 删除 `findActiveExploreRecord` 对旧定时队列的兼容分支。
- 历史战报和已结算记录继续可读，不参与新结算。

### 5.2 共享类型与客户端

- 删除 `ExploreRequest.count`、`ExploreCurrentResponse` 和旧领取响应。
- `ActionCurrentResponse` 增加结算游标、周期进度、累计收益和离线待领取摘要。
- 删除客户端 `currentExplore()`、`claimExplore()` 和按次数 `explore()` 用法。
- 增加统一的长期行动状态刷新和离线收益领取方法。

### 5.3 Web、指令与插件

- 删除 Web 的 `currentExplore` 状态、旧探索卡片、领取探索按钮及旧事件轮询分支。
- 删除帮助中的 `[次数]`、旧倒计时和“完成后领取探索”文案。
- 删除文字指令 `领取探索` 及探索记录 ID 参数。
- 奇遇选择继续隐藏事件长 ID；单条待处理奇遇允许直接选择。
- 插件只显示当前长期行动、周期进度、离线待领取状态和待选奇遇。
- 同一批周期收益、奇遇提示和自动选择结果合并为一条“九州传音”。

## 六、核心规则修复

### 6.1 修炼与探索互斥

- 废弃长期行动之外单独累计的被动修为领取路径。
- `lastCultivationAt` 不再独立制造另一份可领取时间窗口。
- 修炼和探索统一读取长期行动的结算游标与 8 小时离线上限。
- 迁移后必须保证同一分钟只能归属于一种行动。

### 6.2 装备闭环

现有 `equippedSlot` 字段必须真正生效：

- 增加装备和卸下操作，限制同一槽位只能装备一件法宝。
- 装备列表明确区分已装备、未装备、锁定和已分解。
- 探索、九塔、Boss 和排行使用同一套装备战力读取规则。
- 只有已装备且状态为 `active` 的法宝参与战力。
- 淬炼、铭刻、锁定和分解继续复用现有服务；已装备法宝分解前必须先卸下。
- Web 增加法宝管理弹窗，文字端补齐等价指令。

### 6.3 技能闭环

- 保留已有技能学习和技能编组接口。
- Web 增加技能学习、主动技能编组、古宝技能和自动优先级设置。
- 战斗结算实际应用技能效果，不能只把技能名写入战报。
- 探索、九塔和 Boss 使用同一编组快照，战报保存本次使用的技能和规则版本。
- 技能调整只影响之后生成的战斗，已经生成的战报不回算。

### 6.4 统一战力

统一输入：

```text
大境界 + 小境界阶段 + 当前等级 + 已装备法宝词条 + 有效技能修正
```

要求：

- 探索和多人模块调用同一个战力服务。
- 不得再把所有未分解法宝都计入战力。
- 战力和胜负原因可在战报详情中追溯。
- 炼体路线使用炼体专属小境界名称，不再返回练气路线名称。

## 七、现有玩法入口补齐

以下工作只接入已经存在的服务和接口。

### 7.1 P1：核心成长闭环

| 模块 | 当前缺失 | 修改内容 |

| 活动 | 只有进度按钮，规则不可见 | 调用活动详情，展示资格、行动令成本、次数限制、周期和奖励后再允许参与 |

统一 UI 规则：

- Web 以独立居中弹窗和结构化 UI 为主，文字指令为辅。
- 功能弹窗关闭后返回功能面板，不把结果写成替代 UI 的大段终端文本。
- 所有长 ID 只用于内部请求，不直接展示给普通玩家。
- 操作按钮使用统一尺寸、颜色、禁用态和反馈组件。
- 背包物品、法宝、技能、活动奖励和战报都提供可读详情。

## 八、退役残留清理

- 从 `GameOverviewResponse` 删除 `new_player_route`。
- 删除 `buildNewPlayerRoute`、`primary_action_hint`、`primary_step_id` 和“下一步”相关文案。
- 删除插件中的今日路线和推荐行动摘要。
- 更新过期测试，不再断言按次数探索、领取探索或今日路线。
- 历史设计文档保留档案标记，但现行文档不得继续引用旧流程作为验收标准。

## 九、实施顺序

### 阶段 0：建立回归基线

- 固化当前境界、钱包、物品、任务、奇遇和战报测试数据。
- 为立即结束长期探索、探索后补领修为和新旧探索并存建立失败用例。
- 记录当前 Web 和指令端所有入口，作为删除与替换清单。

### 阶段 1：重构长期行动

- 完成行动记录和结算记录迁移。

## 十、测试计划

### 10.1 长期行动单元测试

- 59 分钟不产生完整小时在线批次，但行动进度正确保留。
- 60 分钟触发一次在线批量结算。
- 1440 分钟累计恰好生成 21 场探索，不多不少。
- 开始后立即结束生成 0 场奖励。
- 结束时只补齐未结算的完整分钟。
- 同一结算窗口重复请求不重复发奖。
- 两个不同幂等键并发补算同一窗口，只产生一组奖励和战报。
- 服务重启后可以从 `settledUntil` 继续结算。
- 离线 2 小时按 2 小时计算，离线 12 小时只按 8 小时计算。
- 领取离线探索后不能再领取相同时段的离线修炼。
- 切换行动不会继承上一行动不足一分钟的余量。

### 10.2 探索与奇遇集成测试

- 文字端和 Web 只能开始长期探索。
- 带次数的探索请求被拒绝，不进入旧流程。
- 在线周期收益直接入账并合并通知。
- 离线收益在点击领取前不入账，领取后一次入账。
- 每场探索生成独立战报，奖励汇总与战报之和一致。
- 奇遇只能由有效探索场次触发。
- 奇遇手动选择、超时自动选择和重复请求均保持幂等。
- 结束探索后不再出现“领取探索”按钮。

### 10.3 战斗与装备测试

- 未装备法宝不增加战力。
- 同一槽位不能装备两件法宝。
- 探索、九塔和 Boss 对同一角色返回一致基础战力。
- 技能编组变化会影响之后的战斗结果或战斗过程。
- 战报能够说明境界、装备和技能的有效修正。
- 炼体角色显示正确的小境界名称。

### 10.4 Web 闭环测试

- 所有功能按钮打开独立 UI 弹窗，不退化为命令输出页。
- 单方、装备、技能、宗门、内天地、活动、排行和阵营均可完成实际操作。
- 未解锁功能不能提交请求，并显示服务端解锁条件。
- 弹窗关闭和子页面返回行为一致。
- 长 ID 不出现在任务、奇遇和资源操作界面。
- 今日路线和下一步推荐不再显示或请求。

### 10.5 数值与安全测试

- 标准免费玩家的探索收益仍符合当前境界日收益预算。
- 21 场/日的标准探索收益不会因小时结算被放大。
- 修炼与探索时间互斥后，成长速度仍满足约第 20 天筑基、第 50～55 天进入金丹。
- 钱包、物品、修为、任务和行动状态的并发结算结果正确。
- 月卡、VIP、外观和收藏不提高探索掉落、战力倍率或公共玩法贡献倍率。

## 十一、迁移与发布要求

测试环境：

- 允许执行 `npm run db:reset`。
- 重置后重新生成州域、任务、基础配置和新角色数据。
- 删除测试数据库中的旧待领取探索，避免新旧记录混用。

生产环境：

- 不执行数据库重置。
- 迁移前停止创建旧按次数探索。
- 已完成未领取的旧探索按旧快照一次性结清；进行中的旧探索按迁移时刻结算后关闭。
- 旧记录转为只读历史数据，不映射为新的长期行动。
- API、Web、插件和共享客户端必须同步发布，不保留旧探索兼容入口。

发布顺序：

1. 数据库迁移和服务端双读准备。
2. 暂停旧探索创建并结清旧记录。
3. 启用长期行动新结算。
4. 发布 Web、插件和客户端。
5. 删除临时迁移分支与旧接口。

## 十二、最终验收标准

- 玩家只能开始长期探索，无法进入按次数探索。
- 在线探索持续结算，不需要结束后领取整段收益。
- 离线探索最多计算 8 小时，并通过 Web 弹窗确认领取。
- 立即结束探索无法获得保底场次或资源。
- 修炼和探索不存在同一时段重复收益。
- 装备与技能真实参与探索、九塔和 Boss 战斗。
- 已有核心系统在 Web 中均有结构化操作入口。
- 今日路线、下一步推荐、领取探索和长 ID 全部退出玩家界面。
- 所有奖励动作具备玩家锁、条件更新、幂等记录和可追溯日志。
- 自动化测试、构建和数值模拟通过，测试结束后 API、Web 与临时后台进程全部终止并释放端口。
