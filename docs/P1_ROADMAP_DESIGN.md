# 《择日飞升：九塔封魔》P1 功能开发路线图 v0.2

## 一、定位

本文把 P1 从“公开测试后的中后期内容”调整为“先补体验厚度，再扩中后期内容”的可执行路线。当前 P0 / MVP 规则闭环已成立，但 Web 玩法仍偏向一次点击立即结算；如果直接扩九州、内天地和阵营，会把这种单薄反馈复制到更多系统。因此 P1 v2 先补数值模拟和 Web 过程反馈，再推进九州全域、内天地、仙魔路线、完整排行、节日活动和合服 dry-run。

P1 核心原则：

- 不改变 P0 已确定的边界：随时玩、异步参与、每日 30 分钟核心收益、付费不直接决定全服胜负。
- Web 体验优化不改变服务端结算，不增加奖励倍率，不增加强制在线时间，不破坏一键提交。
- 客户端只展示过程和推荐，不计算奖励、贡献、抽卡结果、战斗胜负和风控结论。
- 插件默认仍是小状态卡片，点击后打开展开窗口，不做完整 Web 替代。
- P1 不重做 P0 规则，只在 P0 之上增强体验和中后期内容。
- 合服在 P1 只做 dry-run 和执行预留，不默认执行真实合服。

## 二、P1 执行顺序

| 顺序 | 阶段 | 模块 | 推荐原因 |
| ---: | --- | --- | --- |
| 1 | P1-0 | P1 文档与接口预备 | 先统一 Backlog、API、数据模型、配置和 QA，避免研发按旧顺序开工 |
| 2 | P1-1 | 数值模拟工具 | 先验证成长、经济、付费和服务器规模，避免后续内容数值失控 |
| 3 | P1-2 | Web 玩法体验优化 | 优先修复“点一下就结束”的体验，再扩展更多玩法 |
| 4 | P1-3 | 九州全域 | 开放扬、荆、豫、梁、雍，支撑中后期章节和九塔长期争夺 |
| 5 | P1-4 | 内天地完整养成 | 化神后核心长期成长，需要和九州派驻、资源循环打通 |
| 6 | P1-5 | 成仙 / 成魔完整路线 | 承接化神后阵营锁定、转道和终局奖励 |
| 7 | P1-6 | 完整排行与称号继承 | 公开测试需要长期目标、荣誉展示和纪元结算复盘 |
| 8 | P1-7 | 节日活动 | 在核心系统稳定后提供运营节奏和回流目标 |
| 9 | P1-8 | 合服 dry-run | 等真实活跃数据出现后先演练影响，不提前上线真实合服执行 |

## 四、Web 体验增量字段

P1-2 的目标是让玩法“看起来在发生”，但不把客户端变成结算端。现有探索、战斗、九塔、Boss、PVP、洞府、炼丹、炼器、抽卡接口可以增加以下可选展示字段：

| 字段 | 说明 | 边界 |
| --- | --- | --- |
| `timeline` | 展示步骤、战斗回合、事件节点、生产过程或抽卡演出节点 | 只展示服务端已结算结果，不允许客户端追加奖励 |
| `delta_summary` | 行动前后资源、贡献、进度、状态变化摘要 | 必须由服务端生成，前端只渲染 |
| `next_recommendations` | 下一步推荐行动、缺口材料、可参与玩法 | 不能暗示付费必胜，不强制玩家固定时间上线 |
| `reason_tags` | 胜负原因、衰减原因、未开放原因、风控提示标签 | 必须和服务端规则一致，不隐藏损失边界 |

Web 体验优化验收：

- 不增加强制在线时间。
- 不增加奖励倍率。
- 不破坏一键提交和批量便利。
- 每个核心玩法都有过程反馈、状态变化和奖励总结。
- 移动端文字不溢出、不遮挡，不新增营销页。

## 五、重要 API 与配置变化

P1 新增接口分组：

| 分组 | 接口前缀 | 说明 |
| --- | --- | --- |
| 内天地 | `GET/POST /api/inner-world/*` | 派驻、收取、升级、生灵培养、九州支援 |
| 阵营路线 | `GET/POST /api/factions/*` | 路线选择、转道任务、声望、宗门立场冲突校验 |
| 活动 | `GET/POST /api/events/*` | 活动列表、进度、奖励领取、活动公告 |
| 合服 dry-run | `POST /api/admin/merge/dry-run` | 生成合服影响报告，不改真实数据 |

P1 新增配置类型：

- `simulation_config`
- `province_full_config`
- `web_experience_config`
- `inner_world_config`
- `faction_route_config`
- `era_rank_config`
- `activity_template_config`
- `merge_dry_run_config`

所有 P1 状态变更接口继续使用 `Idempotency-Key`，并返回记录 ID、配置版本、奖励版本和风控状态。

## 七、风险与边界

- Web 体验优化不能演变成客户端判定，所有奖励和贡献仍以服务端记录为准。
- 九州全域和内天地会显著增加材料产出，必须先跑数值模拟工具。
- 内天地不得产出付费货币、九大古宝本体和限定法宝。
- 成仙 / 成魔路线不能让单一阵营滚雪球；弱势补偿只提高参与收益，不直接判胜。
- 排行奖励以荣誉、外观、纪念和少量非核心材料为主，不发唯一战力道具。
- 活动全部支持异步参与，不要求固定时间上线。
- 合服 dry-run 必须不改真实数据，真实合服执行必须人工确认。

## 八、验收场景

- P1 模块能按 P1-00 到 P1-27 拆成研发任务，而不是继续停留在 Backlog 高层描述。
- P1-2 完成前不扩展九州全域前端，避免把单薄结算体验复制到更多系统。
- 30 / 100 / 300 活跃玩家的数值模拟能生成成长、经济、材料、抽卡和 PVP 强度报表。
- Web 核心玩法均能展示过程反馈、状态变化、奖励总结和下一步推荐。
- 九州全域中幽州不作为系统州名。
- 内天地、阵营、排行、活动和合服 dry-run 都有对应接口、数据、配置和 QA 入口。
- P1 内容不破坏 P0 的随时玩、30 分钟核心收益、强 PVP 边界、脚本行为风控和付费隔离规则。
