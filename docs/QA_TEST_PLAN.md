# 《择日飞升：九塔封魔》QA 测试计划 v0.5

## 一、定位

本文定义 MVP 到公开测试阶段的质量验证计划。测试目标是确保核心玩法可玩、可追溯、可运营、可平衡，并重点覆盖随时玩、30 分钟核心收益、强 PVP 边界和付费隔离。

## 四、核心功能用例

新手闭环：

| 用例 | 预期 |
| --- | --- |
| 创建角色选择练气 | 成功进入九州地图 |
| 领取离线收益 | 修为和灵石增加，写货币日志 |
| 完成第一次探索 | 生成行动记录和战斗日志 |
| 炼制第一颗丹药 | 成功或失败均有明确反馈 |
| 炼制第一件普通法宝 | 生成词条和道具实例 |
| 提交第一次九塔行动 | 获得贡献和奖励记录 |
| 查看今日任务 | 能明确下一步目标 |

生产与幂等：

| 用例 | 预期 |
| --- | --- |
| 炼丹接口重复提交同一幂等键 | 返回同一 `alchemy_record_id`，不重复扣材料 |
| 服用同阶同类第 1、3、4、10、11 颗丹药 | 效果符合 100%、100%、50%、50%、10% |
| 炼器生成法宝 | 生成 `equipment_instance` 和词条记录 |
| 淬炼锁定词条 | 被铭刻锁定的词条不变化 |
| 炼器结果检查 | 不会产出九大古宝 |
| 古宝日课第 4 次主动触发 | 被拒绝或提示次数已满，不消耗目标道具 |

异步活动：

| 用例 | 预期 |
| --- | --- |
| 玩家任意时间提交九塔行动 | 不要求固定开战时间 |
| 玩家错过结算时间 | 已提交贡献不丢失 |
| 阶段已结束后提交结算 | 返还行动令或进入补偿 |
| 低活跃服务器推进 | NPC 兜底生效但不发排行大奖 |

## 五、PVP 测试

| --- | --- |

## 六、抽卡与付费测试

| 用例 | 预期 |
| --- | --- |
| 九大古宝池单抽 | 结果只能是九大古宝之一 |
| 月卡赠抽过期 | 当日未用则过期，不转仙玉 |
| 小月卡每日赠抽 | 每天 1 次并计入保底 |
| 大月卡每日赠抽 | 每天 2 次并计入保底 |
| VIP 抽九大古宝池 | VIP 不提供额外赠抽 |
| 九大古宝残页合成抽取 | 30 残页合成 1 抽，结果只能是九大古宝之一并计入保底 |
| 付费仙玉抽九大古宝 | 返回未开放，不扣仙玉、不写成功抽卡记录、不计保底 |
| `reserved_paid_jade` 抽九大古宝 | 返回未开放，不扣仙玉、不写成功抽卡记录、不计保底 |
| 绑定仙玉抽限定池 | 被拒绝 |
| 重复古宝 | 转化碎片和器魂，不叠加被动 |
| 订单重复回调 | 只到账一次 |
| paid 未 delivered 订单补单 | 核验后可补单 |
| 购买 65536 积分仙玉包 | 到账 65536 付费仙玉，赠送只进入绑定或收藏类奖励 |
| 纪元消费 10 万积分 | 形成单流派毕业感，但不突破 PVP 强度上限 |
| 纪元消费 50 万积分 | 接近收藏毕业，但不提高九塔和 Boss 贡献倍率 |

## 七、经济与风控测试

| 用例 | 预期 |
| --- | --- |
| 交易绑定道具 | 禁止上架 |
| 交易付费产物 | 禁止上架 |
| 异常高价交易 | 标记风控 |
| 同设备互倒材料 | 交易冷却或收益衰减 |
| 宗门新成员提取高价值材料 | 24 小时内禁止或需审批 |
| PVP 刷分 | 收益延迟结算并标记审核 |

交易行：

| 用例 | 预期 |
| --- | --- |
| 上架非绑定基础材料 | 成功生成 `trade_listing` |
| 上架月卡产物、VIP 产物、限定本命法宝、九大古宝 | 被拒绝并写风险日志 |
| 重复购买同一上架单 | 幂等返回同一结果或提示已成交，不重复转移物品 |

脚本行为与权益越权：

| 用例 | 预期 |
| --- | --- |
| 免费账号伪造批量 20 次 | 服务端拒绝或截断为免费上限 |
| 免费账号调用大月卡托管队列 | 返回无权限，不创建托管计划 |
| 免费账号伪造自动策略槽位 | 服务端按当前权益重新计算并拒绝越权槽位 |
| 高频固定间隔请求 | 风险分增加，可触发限频，但普通收益不被无故吞掉 |
| 普通脚本点击领取和探索 | 不直接封禁，只记录行为日志和限频结果 |
| 同一 PVP 目标连续攻击 | 触发收益衰减和风险记录 |
| 同设备多账号刷九塔补给 | 贡献进入延迟结算并标记审核 |
| 风控延迟收益后台审核 | 可发放、回滚或解除标记，并写 GM 操作日志 |

P1 Web 体验验收：

| 用例 | 预期 |
| --- | --- |
| 普通探索提交 | 仍可一键完成，同时展示时间线、事件节点、奖励总结和下一步推荐 |
| 自动战斗战报 | 展示技能释放、伤害、治疗、法宝触发、胜负原因和自动 / 手动标识 |
| 九塔行动提交 | 展示提交前后塔状态、全服进度和个人贡献变化 |
| Boss 镜像挑战 | 展示阶段血量、个人贡献、奖励摘要和未结算原因 |
| PVP 攻防 | 展示防守镜像、胜负原因、收益衰减和损失边界 |
| 宗门建设 / 仓库 | 展示建设贡献、仓库流转摘要、风控或审批原因 |
| 洞府收菜 | 展示设施状态、产出变化和下一步升级建议 |

| 抽卡 / 古宝 | 展示保底变化、重复转化和来源限制 |
| 移动端展示 | 文字不溢出、不遮挡，不需要营销页 |

P1 Web 体验边界：

- 不增加强制在线时间。
- 不增加奖励倍率。
- 不破坏一键提交和批量扫荡。
- 不让客户端决定奖励、贡献、战斗、抽卡或风控结果。
- 过程反馈必须来自服务端记录或可追溯派生数据。
- 插件展开态只展示轻摘要，不替代完整 Web；摘要至少覆盖最近战报、九塔、古宝提醒和跳转入口。

## 十一、压测建议

| 场景 | 指标 |
| --- | --- |
| 批量行动提交 | 高峰请求不重复扣令、不丢记录 |
| 高频脚本点击 | 限频生效，不影响正常低频请求 |
| 世界 Boss 阶段结算 | 排行快照正确，奖励可异步发放 |

| P1 活动结算 | 异步活动奖励和排行快照不重复发放 |

## 十二、验收标准

- P0 用例全部通过才可进入 MVP 测试服。
- 任何付费、抽卡、订单、货币幂等问题必须阻断上线。
- PVP 防骚扰、新手保护和收益衰减必须通过回归测试。
- 脚本行为测试必须确认：不禁止普通脚本点击，但脚本不能突破行动令、权益档位、奖励公式、托管权限和贡献衰减。
- 配置发布、回滚、奖励禁止项校验必须通过。
- 10 万到 50 万积分毕业模型必须通过付费强度、抽卡成本、订单追溯和全服贡献边界测试。
- 九大古宝当前只能通过月卡赠抽或残页合成抽取，仙玉预留入口不能造成扣费、结果或保底变化。
- 鱼排插件默认小卡片和点击展开复杂窗口的交互必须通过验收。
- P1-2 Web 体验优化完成后，核心玩法必须都有过程反馈、状态变化、奖励总结和下一步推荐。
- P1 内容不得破坏随时玩、30 分钟核心收益、强 PVP 边界、脚本行为风控和付费隔离规则。
- 合服 dry-run 只生成报告，不执行真实合服。
- 关键 bug 修复后必须补充回归用例。
