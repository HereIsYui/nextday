# 《九州》重构核心资产清单

> 本文用于为下一轮重构建立共同基线。它不延续旧版本的页面结构、日课流程或功能优先级，只盘点已经具备价值的资产，并明确哪些内容应冻结、改造或废弃。

## 一、当前问题判断

项目不是“功能不够”，而是同时运行了两套互相争夺主视线的游戏：

- 旧方向是“文字修仙日课”：探索、炼丹、九塔、任务、活动和成长面板组成每日循环。
- 新方向是“九州城池战略”：出生州、主城、土地、行军、城防、分城、宗门和州势组成持续世界。

两套方向都被做进了同一个 Web 页面和同一批接口中，导致玩家不知道自己是在扮演修士、城主还是任务执行者。重构不能继续做“把旧功能换个入口”，而要先选定唯一主幻想，再将其他系统降为其支撑。

建议的新项目工作名为“九州修仙领地战略游戏”，其唯一主幻想是：**玩家作为修士城主，从一块地开始建设仙城、扩张领地，并与他人共同改变九州版图。**

修仙不是另一套日课主线，而是城主与军队的能力成长；炼丹、炼器不是独立小游戏，而是城池建设、出征和防守的战略补给。

## 二、可复用的核心资产

### 1. 世界与地图资产：直接保留

| 资产 | 现有能力 | 重构中的定位 |
| --- | --- | --- |
| 九州州域设定 | 九个州的主题、地貌、关隘、州府与九塔 | 世界地理、资源倾向与竞争舞台 |
| 8,888 区块地图 | 州级形状、坐标、地形、九塔 4×4 区域、视口加载 | 新项目的唯一主画布 |
| 地形系统 | 平原、沼泽、森林、山地、沙漠及对应产出 | 土地经营与扩张选择 |
| 区块产权 | 出生分配、相邻购买、清野资格、幂等结算 | 领地扩张的基础规则 |
| 战略地标 | 关隘、州府、九塔、资源点与独立控制权 | 中后期宗门协作与州势竞争 |
| Canvas 地图渲染 | 缩放、拖拽、选中、分块加载、城池与地形贴图 | 地图浏览与操作的技术底座 |

主要代码位置：`apps/api/src/world`、`apps/web/app/page.tsx` 中的 `WorldMapScreen`、`apps/web/public/maps`、`prisma/schema.prisma` 中的领地与行军模型。

### 2. 城池与经济资产：直接保留，但重排入口

| 资产 | 现有能力 | 重构中的定位 |
| --- | --- | --- |
| 主城与分城 | 建城、等级、建筑、资源、保护、分城与驻防 | 玩家长期资产与地图落点 |
| 城池资源 | 灵石、粮草、矿材、灵木、灵草、道兵 | 建设、生产、行军和防守的共同经济 |
| 建筑系统 | 城主府、仓库、兵营、修炼及生产建筑的升级队列 | 城内视角的核心交互 |
| 行军与清野 | 行军队列、抵达、清野、战报、购买资格 | 从地图到领地的第一条可玩链路 |
| 驻防与军队预设 | 目标兵力调配、道兵守恒、出征与驻防预设 | 领地防守与前线调度 |
| 围城与掠夺 | 主城保护、分城可夺、城防、战报和恢复路径 | 后期玩家对抗，必须延后开放 |

主要代码位置：`apps/api/src/city`、`apps/api/src/world/world.service.ts`、`prisma/schema.prisma` 中的 `PlayerCity`、`MarchQueue`、`WorldBlockOwnership`、`TerritoryGarrison`、`SiegeRecord`。

### 3. 修仙内容资产：改造成“城主成长层”

| 资产 | 现有能力 | 应改造为 |
| --- | --- | --- |
| 境界与突破 | 九大境界、突破条件、战力与解锁规则 | 城主等级门槛，解锁建筑、队列、兵种、分城与战略地标资格 |
| 技能与预设 | 技能记录、主动技能、本命技能与自动顺序 | 城主出征与守城战术配置 |
| 炼丹 | 丹方、材料、品质、服丹记录 | 治疗、行军补给、突破辅助与短期战术增益 |
| 炼器 | 装备、词条、淬炼与铭刻 | 将领装备、城防器械、攻城器械与阵法部件 |
| 内天地与洞府 | 资源生产、派遣和成长内容 | 后期领地建筑或个人修炼侧室，不单独抢地图主循环 |
| 探索战斗与怪物池 | 州域怪物、战斗日志、奖励与战报 | 清野、秘境、资源点争夺前的 PvE 内容 |

主要代码位置：`apps/api/src/game`、`apps/api/src/production`、`apps/api/src/inner-world`、`apps/api/src/multiplayer`。

### 4. 多人、叙事与运营资产：保留为支撑能力

| 资产 | 可复用价值 | 新项目中的使用边界 |
| --- | --- | --- |
| 宗门、集结、外交、雇佣 | 已具备组织、成员、仓库与异步协作基础 | 只服务于共同防守、争夺战略地标和领地互助 |
| 战功、日榜、周榜、长期荣誉榜 | 已改为永久世界的竞争与普通资源回补 | 不做世界重置，不以付费提升排名倍率 |
| 九州大事记与个人战报 | 能记录公共大事件与个人操作结果 | 大事记记录地图变化；个人战报记录行动因果 |
| 配置、审计、幂等、风控 | 配置版本、钱包日志、审计日志、限频与幂等键 | 继续作为生产级安全底座，不进入玩家界面 |
| 鱼排 OAuth、插件与后台 | 账号、插件轻入口、运营后台已有基础 | Web 主体验稳定后再接回，不反向约束核心玩法 |

主要代码位置：`apps/api/src/social`、`apps/api/src/multiplayer`、`apps/api/src/story`、`apps/api/src/risk`、`apps/api/src/admin`、`apps/api/src/auth`。

## 三、必须冻结的旧资产

下列内容不是立刻删除，而是停止继续开发，保留数据和接口以便迁移、测试或回溯：

| 旧资产 | 冻结原因 | 处置方式 |
| --- | --- | --- |
| “今日修行”首页与日课路线 | 与地图扩张主循环竞争，形成任务面板感 | 标记为旧体验，不再作为默认登录页 |
| 巨型单页 Web | `page.tsx` 已超过 12,000 行，承载地图、城内、日课和所有详情 | 新项目不再扩写；新界面从独立路由和组件边界开始 |
| 旧三栏、Tab、事务抽屉布局 | 为文字日课服务，无法承载地图和城内沉浸感 | 只保留可迁移的操作组件与反馈模式 |
| 九塔封魔日常主线 | 九塔在城池战略中应是州级战略地标，不是每日签到 | 保留世界观、地标与事件素材，删除日课优先级 |
| 赛季、纪元重置叙事 | 已与永久世界方向冲突 | 仅保留迁移历史，不再新增赛季接口或页面 |
| 大量并列的任务、活动、收藏入口 | 造成“所有功能同时可见”的迷路体验 | 未来按地图、城内、宗门三个上下文分别开放 |

## 四、推荐的新项目边界

### 1. 第一版只保留两个玩家空间

1. **九州地图**：玩家看世界、定位城池、选择区块、出征、购买土地、处理行军和查看他人领地。
2. **我的城内**：玩家管理资源、建筑、仓库、兵营、修炼、生产和防守预设。

地图与城内之间通过主城图标和“返回九州”切换。不要在任一空间内塞入全量功能导航。

### 2. 第一版只有一条完整主循环

```text
出生平原建主城
  -> 收取并投入资源
  -> 升级城主府 / 仓库 / 兵营
  -> 派队清理相邻野地
  -> 购买相邻区块
  -> 获得地形产出或建设位
  -> 扩军、驻防、建立分城
  -> 参与关隘、九塔和宗门目标
```

每一步都必须在地图上留下可观察的结果：城池变大、土地归属变化、资源结构变化、行军状态变化或战略地标控制变化。

### 3. 修仙系统的明确职责

- 境界决定“能建设什么、能带多少道兵、能开几支行军、能否参与何种战略行动”。
- 炼丹提供补给和突破辅助，不做独立的每日点击任务。
- 炼器提供城防、军械和将领配置，不做脱离地图的数值堆叠。
- 技能决定清野、攻城和守城的战术，不做另一个菜单式战斗游戏。

## 五、重构时不可继承的技术债

- 不从当前 `apps/web/app/page.tsx` 继续拼接新 UI；该文件只作为行为和数据查询的参考。
- 不让新地图依赖旧 `ActiveTab`、今日路线或巨型全局状态。
- 不在地图区块上堆放多个按钮；所有行动只在稳定的区块检查器中显示一个主行动。
- 不让 API 同时返回“旧日课视图”和“新战略视图”的混合大对象；按地图、城内、行军、宗门拆成明确读模型。
- 不把早期 PvP、宗门、榜单和付费入口提前放到新手首屏；先验证出生、建设、清野、购买、产出这条单人闭环。

## 六、建议的重构阶段

| 阶段 | 目标 | 交付物 |
| --- | --- | --- |
| N0：冻结与取舍 | 停止旧首页和日课扩展，确定唯一主幻想与资源表 | 本文、核心循环规格、废弃清单 |
| N1：地图垂直切片 | 用一个州完成出生、主城、清野、购买、地图反馈 | 新地图路由、区块检查器、行军摘要、战报摘要 |
| N2：城内垂直切片 | 用城主府、仓库、兵营与一类资源建筑验证建设循环 | 独立城内路由、建筑升级、资源收取、军队调配 |
| N3：成长接入 | 将境界、炼丹、炼器和技能改造成城主及军队能力 | 解锁表、补给链、出征与守城配置 |
| N4：领地深度 | 分城、地形专属设施、驻防、运输和资源网络 | 领地网络、分城建设、地形产出差异 |
| N5：多人战略 | 宗门集结、关隘、州府、九塔、外交与大事记 | 战略地标争夺、协作战报、州势展示 |
| N6：运营接入 | 榜单、活动、鱼排插件、后台与付费便利功能 | 非破坏性运营能力，不改变核心胜负倍率 |

进入下一阶段前的门槛：N1 必须让新玩家在 20 分钟内清楚回答“我的城在哪里、下一块地为何值得拿、拿到后有什么变化”；N2 必须让玩家在不打开旧日课页面的情况下完成一次资源到扩张的循环。

## 七、代码与数据迁移原则

1. **保留数据库，不复制旧体验。** 现有 Prisma 模型和迁移是可用资产；新玩法优先新增读模型、状态表和迁移，不删除已部署迁移。
2. **保留结算安全，不保留页面耦合。** 幂等键、钱包日志、审计、权限、限频和战报写入应直接复用。
3. **新旧接口并行一段时间。** 新战略 API 使用清晰的新读模型；旧日课接口只维持兼容，不再增加字段。
4. **先搬规则，再搬展示。** 例如保留炼丹材料与品质结算，再重新设计它在城内的入口和结果。
5. **迁移必须可回滚。** 每个阶段通过功能开关切换新入口，不用一次性删除旧页面和数据。

## 八、下一步的唯一决策

在写任何新功能前，需要确认以下一句话是否成立：

> 玩家打开游戏的第一件事，是在九州地图上看见自己的城和下一块值得经营的土地；其余所有系统都帮助他做出并完成这个决定。

若认可这句话，下一项开发不应是继续修旧 Web UI，也不应增加新的日课、活动或战力系统，而应先做 N1 的一州地图垂直切片，并从旧首页中彻底隔离出来。
