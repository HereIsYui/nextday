# 文字修行玩法说明

## 目标

主游戏以确定性中文命令推进个人修行。Web 页面只保留状态摘要、叙事日志、命令输入、帮助、章节卷轴与最近战报；九州是游历地点和故事舞台，不再承载城池、领地或战略占领。

## 指令交互

- `GET /api/game/command-help` 返回分组帮助、别名和规范语法。
- `POST /api/game/commands` 只解析确定性命令，不调用自然语言模型。
- 每次命令返回按顺序排列的日志、需要刷新的状态区域和下一步建议。
- 变更类命令沿用鉴权、幂等键、审计日志和原有结算服务。

首版覆盖状态、修炼、突破、探索、奇遇、洞府、任务、服丹、炼丹、炼器、单方、九塔、卷轴和战报。

## 自研丹器

炼丹与炼器没有默认配方或配方列表。玩家提交可投炉材料清单，服务端会规范化材料及数量；同一无序组合稳定对应一个基础产物模板，成功率、品质、数值和词条仍由本次炼制结算。

只有带有丹材或器材标记的专用材料可以投入对应炉位。它们来自州域探索、洞府收取或九塔事件，不能误消耗其他系统资源。

成功记录可以保存为单方。单方保存材料快照、结果模板、规则版本和发现者；作者可公开或取消公开。公开单方可被其他玩家检索和复用，但每次炼制仍独立结算品质与词条。失败记录不能保存为单方。

丹药效果只进入既有成长闭环：直接获得修为、提供一次突破辅助，或提供下一次探索增益。法宝保存本次生成的类型、稀有度和词条快照，后续不依赖全局配方。

## 城池退役迁移

`20260804120000_text_game_retirement_and_formulas` 是不可逆迁移。执行 `npm run db:migrate` 时会先调用 `pg_dump`，将备份写入未纳入版本控制的 `backups/text-game-migration/`，备份失败会中止 Prisma 迁移。迁移脚本默认只允许本地数据库；远端发布必须在已确认备份与发布窗口后显式设置 `ALLOW_REMOTE_MIGRATION=true`。

迁移会返还旧城池库存、待领取领地产出和非空药圃中可映射的灵石、灵草、矿材和灵木，并写入迁移审计；即使历史角色缺少钱包记录，也会先补建钱包再入账。粮草、道兵、建筑等级及占领地块不会折现。随后删除城池、建筑、药园、军队、领地、行军、围城和战争结算数据表。
